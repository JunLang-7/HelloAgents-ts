# Learn v0.2.0 upstream API and behavior compatibility matrix

**Status:** planning baseline — this document does **not** claim implementation
parity.

**Tracking issue:** [#68](https://github.com/JunLang-7/HelloAgents-ts/issues/68)

**Upstream authority:** [`jjyaoao/HelloAgents` `3927c6d1decb37737c4c1344fde00ccef55ab1f3`](https://github.com/jjyaoao/HelloAgents/tree/3927c6d1decb37737c4c1344fde00ccef55ab1f3) (`learn_version`, Python 0.2.9)

**Target:** `learn-version`, first npm release `@junlang-7/helloagents@0.2.0`

This is the implementation inventory for the teaching line defined in
[learn-version scope](./learn-version-scope.md). The older
[1.x compatibility contract](./compatibility-contract.md) is useful historical
context only; it is not an API authority for this release.

## How to read the matrix

- **Source** is a path in the immutable upstream commit above. `U` links to
  that exact commit; each row or row group names its precise source path.
- **Destination** is the intended teaching-line source module. It is a target,
  not evidence that the file or export exists today. Names become idiomatic
  camelCase only where TypeScript conventions require it; serialized Python
  fields remain snake_case unless the owning issue records an approved
  difference.
- **Owner** is the _single_ implementation issue responsible for the listed
  planned symbols. `Planned` means no parity assertion and no placeholder is
  authorized. #81 owns the package/subpath export policy and optional-dependency
  loading boundary, but does not take ownership away from the feature issue
  shown for each symbol.
- The direct-import inventory includes every top-level, non-underscore class,
  function, type alias, singleton, and intentional constant declared by an
  upstream module. Imported `logger` objects and private (`_name`) helpers are
  implementation details, not supported public API. Thus a user can locate an
  importable upstream name without treating accidental imports as contract.

| Status           | Meaning                                                                        |
| ---------------- | ------------------------------------------------------------------------------ |
| Planned          | Must be specified, implemented, and tested by its owner before it is exported. |
| Optional planned | Same requirement, but base-package import must not load its optional backend.  |
| Out of scope     | Deliberately not part of Learn 0.2.0; it must not be exported by this line.    |

## Conditional, placeholder, and alias exports

Optional imports must be represented by explicit capability checks or
load-on-use factories. A teaching package import may never eagerly require
MCP, A2A, Qdrant, Neo4j, sentence-transformers, TRL, or evaluation SDKs.
Errors must say which TypeScript optional package/capability is missing; they
must not silently substitute a no-op.

### Approved #70 safety differences

- `SearchTool` never performs network I/O on construction or by default. Real
  backends require explicit opt-in and tests inject a backend adapter.
- `TerminalTool` is a deliberate teaching safety divergence from the upstream
  filesystem-capable terminal: it exposes only in-process `echo` and `pwd`.
  `pwd` returns a construction-time workspace label without filesystem access;
  `cat`, `ls`, `cd`, filesystem operands, shell metacharacters, and interpreter
  commands are rejected. It never starts an external command, so `PATH` is not
  an execution boundary.
